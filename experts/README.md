# Expert Library

This directory is the expert library for the AO Conductor Kit. Each expert is a markdown file that defines a domain role (identity + core discipline + knowledge) which is injected into brief templates at dispatch time.

## Structure

```
experts/
├── general/        Domain-agnostic roles (code-writer, reviewer, debugger, ...)
├── project/        Project-specific roles (binance-trading, novel-reader, ...)
├── language/       Language-specific roles (python-expert, lua-expert, ...)
├── tool/           Tool/library-specific roles (ccxt-expert, ffmpeg-expert, ...)
├── index.md        Auto-generated by library-maintainer
├── audit-log.md    Append-only audit history
├── discovery-queue.md   Experts awaiting expert-scout
└── README.md       This file
```

## Rules

1. **Never write expert content from scratch.** Every expert must reference a mature upstream source (OMC skill, official docs, standard spec, authoritative blog).
2. **Expert files are short.** Frontmatter + identity + 5-15 core disciplines + links. No long prose.
3. **Append-only in spirit.** Retire via `library-maintainer`, not by deletion. Deprecated experts get `status: archived`.
4. **One expert, one domain.** Overlaps go through the maintainer's merge/consolidation workflow.
5. **Auto-discovery is allowed.** Missing experts are auto-added by `expert-scout`. The `library-maintainer` audits them on admission and periodically.

## How experts are used

```
User → CEO: "<natural language goal>"
CEO → task-splitter: ao send <splitter> "<goal>"
task-splitter:
  1. Scan experts/index.md for matching experts
  2. If missing → push to discovery-queue.md and ping expert-scout
  3. For each matched expert, read its content and inject into brief body
  4. Generate briefs, issues, spawn workers
Workers: operate with layered expert identities from their brief
Reviewer: audits PRs with code-reviewer expert identity
```

## Frontmatter schema

```yaml
---
name: <identifier>              # kebab-case, globally unique
domain: general|project|language|tool
base-skill: <reference to mature source>
external-sources:               # optional extra links
  - <url>
project-extensions: []          # optional project-local additions
discovered-on: YYYY-MM-DD
discovered-by: <CEO|task-splitter|expert-scout|human>
status: active|archived|draft
---
```
